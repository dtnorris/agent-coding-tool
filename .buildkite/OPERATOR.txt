Repository files

pipeline.yml defines two independent acceptance jobs on act-macos, each bounded
by a 20-minute Buildkite timeout in addition to the unchanged policy watchdog.
bootstrap.yml is the exact hosted YAML for the operator to paste into Buildkite.
acceptance.sh installs frozen bundle dependencies in each job, clears inherited
resolved/development/component/coverage context and qualification settings, and
sets an explicit mode. It creates a new exclusive directory for every invocation.
It binds BUNDLE_GEMFILE to this checkout and canonicalizes TMPDIR so macOS path
aliases cannot split compiler coverage paths from the source census. The probe
also loads Bundler's frozen dependency selection inside the zero-Git guard.

prepare_components.rb provisions ALL packages from split-composition.json alone:
init a private repository, add its exact remote, fetch its full revision, detach
at FETCH_HEAD. The existing Bootstrap resolver verifies actual HEAD and every
Ruby source digest against published files (never development_files) before any
test. Provisioning runs outside the protected test boundary. Nothing is fetched
from mutable main, a sibling checkout, a shared dependency cache or a dev override.
The agent must have noninteractive read access and trusted SSH host configuration
for all three pinned GitHub remotes. Missing credentials/objects/digests fail the
split job; the job never substitutes legacy or offline fixture sources.

verify_implementation.rb is a separate guarded smoke probe: actual YAML loading
and binary capture must execute the pinned act-tasks and act-observability method
sources in split mode. Lifecycle remains verified even though it supplies no
adopted behavior. The probe supplies no coverage hits to acceptance. The complete
command then starts afresh with the existing Ruby rake entry first on PATH and
the zero-Git guard preloaded before Bundler; all existing descendant guards stay.

test/feedback.rb records the actual frozen composition in
report.json, binds the CI scripts/YAML in source provenance, and revalidates the
composition at completion. Existing all-production coverage scope and policy
gates remain intact. The legacy runtime comparator retains its existing shape;
split additionally requires a composition-bound reference. Split runtime is
noncomparable with a legacy reference; no budget or accepted policy is rewritten.
collect_evidence.rb verifies the original local harness evidence in place.
It requires a complete accepted report with the probe's exact composition
and unchanged published manifest. Evidence is neither copied nor uploaded.
Test and verification failures still fail CI. Buildkite receives normal job
logs and exit status; detailed evidence remains on the executing agent.

Recognizing acceptance

Require BOTH named acceptance jobs to be green for the SAME ACT commit. The
upload job alone, probe alone, focused checks, qualification output or a filtered
suite is insufficient. Each acceptance job must print both:

  ACT complete offline acceptance: PASS
  ACT CI legacy complete acceptance evidence: PASS; invocation=...
or, respectively:
  ACT complete offline acceptance: PASS
  ACT CI split complete acceptance evidence: PASS; invocation=...

Each job keeps implementation.json, split-composition.json and acceptance.log
under its local tmp/ci-<mode>.<unique>/artifacts/ directory; split also keeps
provision.log. This directory name does not imply any artifact upload.
The harness prints its separate original local feedback evidence directory.
Check report.json in that printed feedback directory: distinct invocation IDs, head equal to the built ACT
commit, accepted=true, qualification=false, complete_offline_gate=true, all four
complete stages in order, every required process complete and no failures/skips.
The existing runner verifies all inventories and accepted coverage/deadline gates.
Both manifests must match that ACT commit's split-composition.json. Legacy's
implementation.mode is legacy with no packages; split's is split with
qualification=published and all three exact revisions/digests under this job's
private component root. implementation.json must show both executed package
source paths in split and an empty list in legacy. Probe and report compositions
must match. Coverage/case evidence is independently fresh per job/build.

Local verification is focused only; neither full acceptance suite is run locally.
verify_ci.rb uses byte-checked offline package fixtures and synthetic Git refs
for positive/refusal controls; those controls do not prove remote publication.
Real remote provisioning, full compatibility, coverage and accepted policy
enforcement remain CI gates. If either job fails, inspect its retained evidence
and fix the narrow cause or seek an explicit operator policy decision. Do not
lower floors, skip inventories, borrow hits or treat qualification as acceptance.
